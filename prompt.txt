Rework the existing Dotch project into an AI discovery platform for buyers. 
Keep the project's current stack, folders and branding. Change the flow and 
UI as described below. Do not turn it back into a scrolling marketplace.

CORE IDEA
Dotch is an AI search engine for finding businesses, not a feed of listings 
to scroll. The main page is a conversation. Browsing is secondary and only 
happens when the buyer chooses it.

PAGES

1. Landing page (/)
- Simple and clean: Dotch logo, one headline, one short line of text, and 
  one primary button ("Start discovering").
- It must NOT contain the AI conversation or a listings feed.
- The button takes the buyer to the main page.

2. Main page (/discover): the AI search page
- The center of the page is an interactive 3D animated orb (Three.js, or 
  react-three-fiber if the project uses React). It floats and moves gently, 
  reacts to the mouse, glows more while the buyer types, and pulses faster 
  while "thinking".
- Under the orb, the AI greets the buyer with a typed-out text animation: 
  "Welcome. What kind of business are you looking for?"
- Below that is one large input box. No voice is needed. Text only.
- When the buyer submits:
  a) The orb switches to a thinking state for about 1 second.
  b) The app matches the query against sellers in the database 
     (name, category, tags, description, location).
  c) If there are matches, the AI says "I found N businesses for '<query>'" 
     and shows them as result cards INSIDE this page, under the orb. 
     Each card shows logo, business name, category, a short description, 
     location and a "View" button.
  d) If there are no matches, the AI says "Sorry, nothing available for that 
     yet." and offers a "Notify me when a seller joins" button, plus a 
     suggestion to try a different search.
- The buyer can search again at any time. The orb returns to idle.
- There is no infinite scroll of listings on this page.
- A small, quiet "Browse all businesses" link opens the old browse view. 
  It is never the default.

3. Ads (seller sponsored placements)
- Ads are placed AROUND the AI interface: a banner at the top, side 
  columns on desktop, and a strip at the bottom. They must never cover 
  the orb, the input or the results.
- On mobile, hide the side columns and keep the top or bottom strip.
- Ads come from sellers inside the app. Add an "isSponsored" flag and 
  sponsorship fields to the seller data so sellers can pay to appear. 
  Each ad shows the seller's logo, name, tagline and a "Visit" button.
- Label every ad "Sponsored".
- Sponsored sellers may also be ranked higher in search results, but 
  clearly labeled as sponsored.

SEARCH LOGIC
- Start with simple keyword and tag matching with scoring, and rank by 
  relevance.
- Build the matching as one separate function (for example 
  searchSellers(query)) so it can later be swapped for a real AI/LLM or 
  vector search without touching the UI.
- Use the project's existing seller data or database. If none exists, 
  create realistic sample sellers across different categories.

DESIGN
- Dark, modern, premium feel. The orb is the hero of the page.
- Smooth transitions between landing page and main page.
- Fully responsive. The orb must stay lightweight and run well on 
  mid-range phones. Fall back to a CSS gradient orb if WebGL is not 
  available.

DO NOT
- Do not add voice or text-to-speech.
- Do not put a scrolling feed on the landing page or the main page.
- Do not remove existing seller or account features. Only restructure 
  the buyer flow.

WHEN DONE
Tell me which files were changed, how to run the project, and where to 
edit the sample sellers and the ad slots.
